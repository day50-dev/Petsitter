Petsitter sits between the tools you already use
and the AI provider they talk to.

Everything passes through here on its way out, and again on its way back. Your tools don’t need to know it’s there, and nothing about the way you work has to change. Three short steps get it running.

1
Set your provider

2
Connect a tool
Point a tool you already use at petsitter. It edits the tool’s own config, and puts it back exactly when you switch off.
3
See what your tool sends
Every request your tool makes, opened up: its system prompt, every message, the tools it offers, and how big it all is.

Simple Advanced

Petsitter is a proxy to your provider. This is where you set where the traffic goes.

Pick a provider, paste your key, and petsitter asks it which models it has. The list comes straight from the provider, so it’s never out of date. Providers marked models only can’t take requests directly, but a gateway like OpenRouter reaches those too.

Set your provider

Some tricks (kennel, multiconsult) route subtasks to a named role, so they reach more than the default model. Set an API key to false (passthrough) to let the client supply its own key.
